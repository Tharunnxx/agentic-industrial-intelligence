# Capstone graphs: generated from real project data

Generated by `scripts/generate_graphs.py`. All numbers come from the saved model run on the official validation split.

## Inputs
- Model: `models/cost_sensitive_model.joblib` (RandomForest pipeline, 113 features = 105 operational + 8 `Spec_`, classes 0–4; no calibration wrapper)
- Data: the configured SCANIA data directory — `validation_operational_readouts.csv`, `validation_specifications.csv`; `validation_labels.csv` read only after inference
- Protocol (same as `services/evaluation_service.py`): latest readout per vehicle + specification row, one prediction per vehicle, 5,046 vehicles
- Cost matrix: stored in the model artifact; rows = actual class, columns = predicted class. Expected cost of choosing class j = Σᵢ P(i)·C[i,j]. Units are project cost units, not currency.

```
    0      7      8      9     10
  200      0      7      8      9
  300    200      0      7      8
  400    300    200      0      7
  500    400    300    200      0
```

## Graph 1 — `01_vehicle_failure_probabilities.png`
Vehicle `22959` (auto: among vehicles where the highest-probability class differs from the minimum-expected-cost class, the one with the largest P(any failure)). Probabilities (%): C0=17.37, C1=26.31, C2=18.54, C3=12.82, C4=24.96. These are raw RandomForest outputs, **not verified as calibrated**. Meaning: the model gives a distribution over failure classes, not a single label.

## Graph 2 — `02_expected_maintenance_cost.png`
Same vehicle. Expected costs: C0=284.32, C1=176.60, C2=103.76, C3=54.88, C4=6.49. Lowest: Class 4; highest probability: Class 1. The Decision Agent can recommend a class other than the most probable one because missing a failure is penalised far more than a precautionary action.

## Limitations
- Probabilities are uncalibrated; do not present them as true likelihoods.
- Graphs 1–2 show one vehicle, selected by the disclosed rule; they illustrate the mechanism, not overall performance.
- Rare classes (1–3) have very few validation vehicles, so per-class results are noisy.
- Only the official validation split is used; no train/test or experiment numbers are mixed in.
- The model was pickled with scikit-learn 1.7.2; run in the environment you trained with.

## Reproduce
`python scripts/generate_graphs.py` from the project root.
